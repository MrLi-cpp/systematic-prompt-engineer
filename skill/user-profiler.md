# 用户画像引擎协议（User Profiling Engine Protocol）

## 画像维度详解

### 核心维度（Core Dimensions）

这三个维度**必须**在生成提示词前确认，否则会导致方向性错误。

#### TOPIC — 核心主题

**定义**：用户想学习/了解的技术、概念或主题。

**提取规则**：
- 从用户输入中提取专有名词、技术术语
- 如果用户输入模糊（如"想学点新东西"），需要追问引导

**追问模板**：
```
你具体想学习/了解的技术或主题是什么？
例如：深度学习框架、某种算法、某个工具链、某个理论？
```

---

#### DEPTH — 目标深度

**定义**：用户希望达到的认知层次。

**等级定义**：

| 等级 | 名称 | 典型用户描述 | 画像标记 |
|------|------|-------------|----------|
| L1 | 概念理解 | "我想了解一下"、"给我个 overview"、"科普一下" | `beginner` |
| L2 | 原理分析 | "深入理解"、"背后的原理"、"数学推导" | `intermediate` |
| L3 | 代码实现 | "教我怎么用"、"给个代码示例"、"我想跑起来" | `advanced` |
| L4 | 工程部署 | "生产环境怎么搭"、"性能优化"、"监控运维" | `expert` |

**追问模板**：
```
你希望达到什么深度？
- 概念层面：知道是什么、为什么
- 原理层面：理解数学推导和核心机制
- 代码层面：能手写/修改代码
- 工程层面：能部署上线并维护
```

**深度锚点规则**：
- 如果用户已学过相关技术 → 可以从该技术到当前技术的"增量"开始，不必从零讲
- 如果用户零基础 → D1（起源）需要更详细的历史铺垫
- L4 通常只在 L3 已确认时才追问，因为大多数学习者不需要到部署层面

---

#### PERSONA — 用户画像

**定义**：用户的身份、背景、学习风格和偏好。

**推断规则**：
- "大一自动化" → 理工科本科生，有微积分/线代基础，编程经验有限
- "工作 3 年的前端" → 有工程经验，熟悉 JS/React，需要快速上手
- "做产品的，技术不太懂" → 需要类比和可视化，避免代码
- 无任何背景信息 → 追问

**追问模板**：
```
方便介绍一下你的背景吗？例如：
- 你是学生还是在职？什么专业/岗位？
- 你已经掌握了哪些相关技术？
- 你更倾向于哪种学习方式：看代码、看公式、看图解、听类比？
```

---

### 上下文维度（Context Dimensions）

这些维度影响生成策略，但不是阻塞性的。

#### BACKGROUND — 已有知识基础

**定义**：用户已经掌握的相关技术/概念。

**重要性**：决定 D1（起源）的详细程度和 D4（对比）的基准选择。

**追问模板**：
```
你已经学过或了解哪些相关技术？
例如：如果你要学 Mamba，你已经了解 Transformer 吗？了解 RNN 吗？
```

**特殊值**：
- `unknown` — 用户不确定 → 使用默认策略（假设中等基础）
- `zero` — 完全零基础 → D1/D2 大幅增加铺垫内容

---

#### LEARNING_GOAL — 学习目的

**定义**：学完这个技术后，用户打算做什么。

**常见类型**：
- `exam` — 应付考试/面试 → 侧重考点、常见面试题
- `project` — 做项目用 → 侧重代码实现和工程细节
- `teaching` — 教别人 → 侧重教学法、练习设计、知识网络
- `research` — 做研究 → 侧重论文脉络、前沿进展、数学严谨性
- `curiosity` — 纯粹好奇 → 侧重趣味性和宏观视角

**追问模板**：
```
你学这个技术是为了什么？
- 做项目/写论文
- 准备面试/考试
- 教给别人
- 纯粹好奇
```

---

#### TIME_BUDGET — 时间约束

**定义**：用户期望拿到文档的时间，或可用的学习时间。

**影响**：
- `urgent`（< 1天）→ 聚焦核心维度，砍掉扩展维度
- `short`（1-3天）→ 标准深度，适量扩展
- `medium`（1-2周）→ 完整深度，充分扩展
- `long`（> 2周）→ 可以增加 L4 维度、更多案例

**追问模板**：
```
你期望多久拿到这份文档？或者你计划花多少时间学习这个主题？
```

---

#### OUTPUT_FORMAT — 输出格式

**定义**：最终文档的呈现形式。

**常见值**：
- `markdown` — 默认，适合网页/编辑器阅读
- `pdf-ready` — Markdown 结构，但分页逻辑适合转 PDF
- `ppt` — 适合演讲/汇报，需要分页和演讲者备注
- `notebook` — Jupyter Notebook 风格，代码可执行
- `slides` — 幻灯片格式，每页有标题+要点+图示

**追问模板**：
```
这份文档最终要导出成什么格式？
- Markdown（网页/编辑器阅读）
- PDF（打印/分享）
- PPT/幻灯片（演讲汇报）
- Jupyter Notebook（可运行代码）
```

---

### 技术维度（Technical Dimensions）

#### STACK — 已有技术栈

**定义**：用户已经使用的编程语言、框架、工具。

**影响**：D6（代码解析）使用该语言，D5（生态）推荐对应工具链。

**追问模板**：
```
你平时用什么编程语言/框架？
例如：Python+PyTorch、JavaScript+React、C++、Go？
```

---

#### PLATFORM — 目标平台

**定义**：代码最终运行的环境。

**常见值**：`cpu`、`gpu`、`mobile`、`web`、`embedded`、`cloud`

**追问模板**：
```
你的代码最终要在什么环境运行？
- 本地 CPU/GPU
- 移动端
- 浏览器/网页
- 嵌入式设备
- 云平台
```

---

### 约束维度（Constraint Dimensions）

#### EXPLICIT — 显式约束

**定义**：用户明确说出的限制条件。

**示例**：
- "必须有数学推导"
- "代码要用 TypeScript"
- "禁止用 Python"
- "必须包含 Mermaid 图"
- "字数不超过 5000"

**处理方式**：直接写入提示词的约束条款，用祈使句表述。

---

#### IMPLICIT — 隐含约束

**定义**：从用户描述中推断出的未明说约束。

**推断规则**：
- "深入学习" → 隐含：需要数学推导、不能是科普级
- "体系化" → 隐含：需要知识网络、演进脉络
- "教我怎么用" → 隐含：需要代码、需要步骤指南
- "快速了解" → 隐含：不能太长、聚焦核心
- "给领导看的" → 隐含：需要宏观视角、商业价值、避免代码细节

**处理方式**：确认画像时向用户展示推断结果，让用户确认或修正。

---

#### ANTI — 反向约束

**定义**：用户明确不要的东西。

**示例**：
- "不要太多数学"
- "不要讲历史"
- "不要推荐商业产品"
- "不要用 Java，用 Python"

**处理方式**：在提示词中用"禁止..."表述，生成时主动排除。

---

## 追问策略矩阵（查库优先版）

### 追问前检查流程

```
识别信息缺口
    ↓
查询画像数据库（profiles.json）
    ↓
该维度在历史画像中有值？
    ├── 是 → 展示给用户确认：
    │         "上次你说 [值]，这次还是吗？"
    │         用户确认"是" → 标记 confirmed，不发追问
    │         用户说"变了" → 追问新值
    └── 否 → 按下方矩阵发起标准追问
```

### 根据画像缺口选择追问

| 缺口类型 | 优先级 | 查库行为 | 追问策略 | 示例 |
|----------|--------|----------|----------|------|
| TOPIC 缺失 | 阻塞级 | 数据库中匹配相关 topic？→ 进入 RESUMING | 直接问主题 | "你想学什么技术？" |
| DEPTH 模糊 | 关键级 | 有历史值 → 确认"上次你说 L2，这次深度一样吗？" | 用场景描述替代等级 | "你想要科普级还是能手写代码？" |
| PERSONA 未知 | 关键级 | 有历史值 → 确认"上次你是研一学生，现在还是吗？" | 身份+背景 | "你是学生还是工程师？什么专业？" |
| BACKGROUND 未知 | 增强级 | 有历史值 → 确认"上次你说学过 Transformer，现在基础有变化吗？" | 相关技术清单 | "你已经学过 Transformer 吗？" |
| STACK 未知 | 增强级 | 有历史值 → 确认"上次你用 PyTorch，这次还是吗？" | 语言/框架偏好 | "你用什么编程语言？" |
| TIME_BUDGET 未知 | 调优级 | 通常不继承，每次单独问 | 时间期望 | "你期望多久拿到？" |
| OUTPUT_FORMAT 未知 | 调优级 | 有历史值 → 确认"上次要 Markdown，这次格式一样吗？" | 格式选择 | "要 Markdown 还是 PPT？" |
| 信息矛盾 | 关键级 | 检查历史值是否与当前表述矛盾 | 确认矛盾点 | "上次你说零基础，这次提到梯度下降——基础有变化吗？" |

### 追问轮次控制

| 轮次 | 追问焦点 | 典型问题数 | 画像置信度目标 |
|------|----------|------------|----------------|
| 第 1 轮 | TOPIC + DEPTH + PERSONA | 2-3 | 0.4 |
| 第 2 轮 | BACKGROUND + STACK + GOAL | 2-3 | 0.7 |
| 第 3 轮 | FORMAT + TIME + 确认 | 1-2 | 0.9 |
| 第 4 轮+ | 澄清矛盾 / 精调 | 1 | 1.0 |

**终止条件**：
- 核心维度全部确认 → 置信度 ≥ 0.8 即可进入 DRAFTING
- 用户说"直接生成" / "够了" / "跳过" → 立即进入 DRAFTING
- 连续 3 轮用户回答"我不确定" → 使用默认策略，进入 DRAFTING

## 画像继承规则

当检测到历史画像时，按以下规则决定继承策略：

| 匹配类型 | 条件 | 继承策略 |
|----------|------|----------|
| **精确匹配** | topic 完全一致 | 继承全部维度，进入 RESUMING 状态，用户选择"沿用"后可直接 DRAFTING |
| **相关匹配** | topic 包含或被包含 | 继承通用维度（persona/background/stack/format），topic 特定维度（D1-D7 内容）重新确认 |
| **部分相关** | 同一领域不同技术 | 继承 persona/background，其他维度重新收集 |
| **无匹配** | 数据库为空 | 新建画像，执行标准 GATHERING |

**通用维度**（跨 topic 可继承）：
- persona（身份一般不会变）
- background（知识基础短期不变）
- stack（技术栈短期不变）
- output_format（偏好短期不变）

**Topic 特定维度**（每次重新确认）：
- topic 本身
- depth（可能因主题不同而变化）
- learning_goal（不同主题目的可能不同）
- constraints（主题特定约束）

**继承后追问示例**：

```
[画像继承 · RESUMING 状态]
我在 2026-05-10 记录过你对 "Mamba" 的画像：
- 目标深度：L2（原理分析 + 伪代码）
- 你的背景：已深入 Transformer，RNN 基础
- 你的身份：研一学生，科研导向
- 输出格式：Markdown

这次你要学习 "Vision Mamba"，与之前相关。

我可以继承的部分：
✅ 身份/背景/格式保持不变
❓ 需要确认：
1. 目标深度还是 L2 吗？Vision Mamba 涉及视觉任务，是否需要增加代码实现维度？
2. 学习目的还是调研报告吗？

你也可以说"全部沿用"直接生成。
```


| 当前状态 | 用户输入特征 | 下一状态 | 动作 |
|----------|-------------|----------|------|
| GATHERING | 回答了追问，无矛盾 | GATHERING | 更新画像，检查是否还有缺口 |
| GATHERING | 回答了追问，有矛盾 | CLARIFYING | 指出矛盾，请求澄清 |
| GATHERING | 核心维度全部确认 | DRAFTING | 生成画像摘要 + 初版提示词 |
| GATHERING | 用户说"直接生成" | DRAFTING | 基于当前画像直接生成 |
| CLARIFYING | 用户澄清了矛盾 | GATHERING | 更新画像，继续检查缺口 |
| DRAFTING | 用户满意 | FINALIZING | 输出最终版本 |
| DRAFTING | 用户提出修改 | REFINING | 根据反馈修改提示词 |
| REFINING | 用户满意 | FINALIZING | 输出最终版本 |
| REFINING | 用户还有修改 | REFINING | 继续修改 |
| FINALIZING | 用户说"再来一份" | GATHERING | 重置画像，开始新主题 |

## 快捷指令表

用户可以在对话中随时使用以下快捷指令：

| 指令 | 效果 |
|------|------|
| `直接生成` | 跳过剩余追问，基于当前画像直接生成提示词 |
| `够了` / `就这样` | 结束当前阶段的追问/修改，进入下一阶段 |
| `我不确定` | 将该维度标记为 unknown，使用默认策略 |
| `换个方向` | 重置画像的某个维度，重新追问 |
| `回到上一步` | 回退到上一个对话状态 |
| `展示画像` | 输出当前完整的画像结构，供用户查看 |
| `简化版` | 降低深度等级（L3→L2，L2→L1） |
| `深入版` | 提高深度等级（L2→L3，L3→L4） |
