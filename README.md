# Systematic Prompt Engineer

一个可复用的 AI Skill，用于通过**多轮画像对话**将用户的口语化、碎片化技术学习需求，转化为可直接交付执行的体系化提示词（Master Prompt）。

## 核心理念

用户通常不知道"好提示词"应该长什么样。他们只会说：

> "我想学 Mamba，要深入一点，有代码和数学"

这个 Skill 的作用就是**把这句话，通过多轮对话翻译成一份精准的用户画像，再基于画像生成结构严谨、维度完整的 Master Prompt**。

**关键区别**：别人做"提示词优化"（已有提示词 → 改得更好），我们做"需求翻译"（口语需求 → 先理解人 → 再写提示词）。

## 使用方法

### 在 Kimi / ChatGPT / Claude 中使用

1. 新建一个对话
2. 将 `skill/system-prompt.md` 的内容作为 **System Prompt**（系统提示词）
3. 直接输入你的口语化需求，例如：

   > "我想学 Vision Mamba，要代码和对比 Transformer"

4. AI 会主动追问，构建你的画像，最终输出可直接复制给另一个 AI 的体系化提示词

### 多轮对话流程

```
你：口语化需求（第1轮）
AI：[画像构建 · 第1轮] → 追问关键信息

你：回答追问（第2轮）
AI：[画像构建 · 第2轮] → 追问剩余信息 或 生成画像摘要

你：确认画像（第3轮）
AI：[画像确认] → 输出最终体系化提示词
```

**轮次取决于需求复杂度**：
- 简单需求（信息完整）：1-2 轮即可生成
- 中等需求：2-3 轮
- 复杂需求（L3+，画像模糊）：3-5 轮

**快捷指令**（对话中随时可用）：

| 指令 | 效果 |
|------|------|
| `直接生成` | 跳过追问，基于当前信息直接生成 |
| `够了` / `就这样` | 结束追问，进入生成 |
| `我不确定` | 该项使用默认策略 |
| `换个方向` | 重置画像某个维度 |
| `展示画像` | 查看当前完整画像 |
| `简化版` | 降低深度（L3→L2） |
| `深入版` | 提高深度（L2→L3） |

### 在 OpenClaw 中使用

将 `skill/system-prompt.md` 作为 Skill 的系统提示词配置，Agent 自动执行多轮画像 → 提示词生成。

## 画像引擎

### 核心画像维度

| 维度 | 说明 | 是否阻塞 |
|------|------|----------|
| **TOPIC** | 核心主题 | ✅ 缺失则无法开始 |
| **DEPTH** | L1/L2/L3/L4 | ✅ 模糊则维度选择错误 |
| **PERSONA** | 身份/背景 | ✅ 未知则内容偏题 |
| BACKGROUND | 已有知识 | ⚠️ 影响 D1/D2 详略 |
| LEARNING_GOAL | 学习目的 | ⚠️ 影响内容侧重 |
| STACK | 技术栈 | ⚠️ 影响 D6 代码语言 |
| TIME_BUDGET | 时间约束 | 调优级 |
| OUTPUT_FORMAT | 输出格式 | 调优级 |

### 深度等级

| 等级 | 名称 | 内容 |
|------|------|------|
| L1 | 概念理解 | 是什么、为什么、适用场景 |
| L2 | 原理分析 | 数学推导 + 对比分析 + 知识网络 |
| L3 | 代码实现 | 伪代码/实现 + 工程细节 + 性能对比 |
| L4 | 工程部署 | 上线配置 + 生产优化 + 监控运维 |

### 状态机

```
GATHERING（信息收集）──→ DRAFTING（草稿生成）
    │                        │
    │（信息矛盾）            │（用户不满意）
    ↓                        ↓
CLARIFYING ←────────────── REFINING（迭代精修）
    │                        │
    │（澄清完成）            │（用户满意）
    └──────────→ FINALIZING（定稿输出） ←─┘
```

## 内容维度库（D1-D8）

| 维度 | 名称 | 说明 | 深度要求 |
|------|------|------|----------|
| D1 | 起源与痛点 | 为什么需要这个技术 | 必选 |
| D2 | 核心机制 | 技术如何工作 | 必选 |
| D3 | 数学直觉 | 公式背后的直觉 | L2+ |
| D4 | 架构对比 | 与相关技术全维度对比 | 必选 |
| D5 | 生态与应用 | 开源实现与工业应用 | L2+ |
| D6 | 代码级解析 | 伪代码与实现细节 | L3+ |
| D7 | 知识网络 | Mermaid 演化树与关系图 | L2+ |
| D8 | 输出格式约束 | Markdown/LaTeX/代码规范 | 必选 |

扩展维度（按领域）：前端(D9/D10)、数据库(D9/D10)、硬件(D9/D10)

## 示例

### 多轮画像示例（推荐先看）

**Mamba 深度学习** — 完整展示从口语需求 → 3轮追问 → 画像确认 → 最终提示词的全过程。

详见 [examples/multi-turn-mamba.md](examples/multi-turn-mamba.md)

### 自适应调整效果

同一主题，不同画像 → 不同生成策略：

| 画像差异 | 生成策略调整 |
|----------|-------------|
| 用户已学过 Transformer | D1 跳过注意力机制铺垫，直接从瓶颈开始 |
| 用户数学基础薄弱 | D3 用"几何直觉"替代"代数推导"，公式密度降低 50% |
| 用户时间紧迫 | 跳过 L4，聚焦 L2-L3 |
| 用户要教别人 | 增加教学法维度（练习设计、知识网络） |
| 用户输出载体 = PPT | D8 增加分页逻辑、每页字数、演讲者备注 |

## 与现有项目的区别

| 项目 | 核心能力 | 与用户画像？ |
|------|----------|-------------|
| **DSPy** | 提示词自动编译优化 | ❌ 不画像，假设用户知道要做什么 |
| **OPRO** | LLM 自我迭代优化 | ❌ 全自动，零人工对话 |
| **PromptPerfect** | 一键润色提示词 | ❌ 单次交互，无追问 |
| **本项目** | **口语需求 → 多轮画像 → 体系化提示词** | ✅ 主动构建用户画像 |
